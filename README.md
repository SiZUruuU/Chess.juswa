Version 0.1 - Chess Board Created...Created by creating a for loop that creates the squares with the help of if statements that identify the parity of the coordination using modulo. 

Version 0.2 - Chess Pieces Printed...Images are imported using a helper method that eases the syntax for locating the image file location. Then initial piece positions are initalized in a separate class that has a method that contains 8x8 arrays 
that hold the child classes through runtime dispatch. Then the pieces are drawn with the 2D Array by using a nested for loop that first scans the columns and labels the row value to a static 0. This part then checks whether the index is null or not. If not, then
it draws the piece by identifying it through a nested switch case where it identifies the color initially, then identifies the piece name, then it uses the column value from the for loop iteration and multiplies that by 100 plus the piece width to get the x position.
y position uses the same process but instead all calculations for y pos in the mother loop holds steady at 0, meaning all pieces are drawn at the topmost part of the board. Once its done, it starts the first iteration of the inner loop where it also handles the same
logic but now the r is iterated with it sharing the c value from the mother loop. The process remains the same. Once its done, it stops and loops back to the mother loop where it repeats the process again. (AI Assistance is used in this version to understand the use of
8x8 arrays and how it functions in the context of chess.)

Version 0.3 - Mouse Clicks Identify Pieces...mouseClicked() method in MouseHandler class takes the x and y positions of the cursor if clicked. These coordinate values are converted to char. This is done by creating char variables that receive its character by using the String.valueOf() function where x or y is the argument and using charAt(0) to take its first character. This is so that the converted coordinates match the 8x8 arrays which allow for more optimized logic. Digits of the original x and y values are then counted by using a Helper method in PieceHandler that divides the x or y value into 10 per iteration using while loop until the value reaches 0 (Solution from in programiz.com). Once digits are set, if digit is less than 3, the char variable using x or y receives '0'. This is because coordinate values less than 100 are much harder to use when taking account the 8x8 array. By instantly giving it '0', it sets the range of that certain value to receive that char value. After this, it reconverts it back to an int by parsing the char into an int. These new values are then plugged into the array to verify if the position is null or not. If not, it takes the name and color of the piece initialized in the PieceHandler's setUp() method. (Some solutions are from stackoverflow and No AI assistance is used in this version. So big win wahahhaha)

Version 0.4 - Implementation of Piece Interaction/Movement (White only)...mouseClicked() method in MouseHandler class was improved upon by taking the initial syntax and adding an extended behavior that allows users to interact with the pieces depending on board state. The method can still identify pieces and its current position but now it can also transfer its data to a new coordinate. This works by using 2 nested if else blocks which rely on the boolean named "piecePressed" for activation. The boolean is used to determine the state of piece interaction. The first nested block handles the behavior where the boolean is false. This state is the initial condition of the board and is also considered the normal state. Here, a new integer variable named "selectRow/Col" is introduced to now receive the parsed int of rowChr/colChr which is used to hold the current position of a pressed piece. The second step is now detecting object presence in the pressed position. If null, It then identifies if the piece is white or black. In this version, it only recognizes white. Next if verified to be white, a local String variable called "name" receives the piece name. It then checks the name which goes through a line of or statements in the if condition (This part doesnt matter as of this moment as it the entire method is currently designed to only handle white pawns). This part then turns the boolean true to trigger the 2nd nested block. Once finished, the 2nd block is triggered which handles if a piece has been selected. Now a new integer variable pair is introduced called "newCol/newRow" to receive the new position of the piece. If the user presses on a null block, the array with the newCol/newRow arguments receive the data of the original position (selectCol/Row) then turns the original position null. After, it turns the boolean back to false. After the 2 blocks have been triggered, a repaint() function is called to redraw the board and pieces. Initially, an error was found that was implemented in Version 0.2 that doesn't reset the yBox value. Because of this, repainting the board would multiply the yBox value by 2, completely seemingly erasing the boxes from the visible board. The yBox initialization was then transferred in the method block to reset its value for every repaint().
